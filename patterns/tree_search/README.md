# Tree Search

A tree where every node is a component: a company's org chart, 31 people in five levels, **generated by a loop** from the data rather than wired by hand. A search goes down the tree as a wave, with everyone on the same level checking **in the same cycle**, and the answers come back up the same way, each manager merging their reports' answers with their own until the CEO holds the result.

```
Who knows Go?
  cycle  1: 1 on level 0
  cycle  2: 2 on level 1
  cycle  3: 4 on level 2
  cycle  4: 8 on level 3
  cycle  5: 16 on level 4
  cycle  6: 8 on level 3
  cycle  7: 4 on level 2
  cycle  8: 2 on level 1
  cycle  9: 1 on level 0
  → 9 of 31 people, found in 9 cycles: Ada (CEO), Eve (Engineer), ...
```

31 people are asked in 9 cycles: a search costs as many cycles as the tree has levels (down and back up), not as many as it has nodes. Every node on a level runs concurrently, with no goroutines or locks in the code.

## How it works

- **The topology comes from the data.** `orgChart` generates the people; `getMesh` walks the tree recursively and adds one component per person, a pipe `down` to each report and one back up from each report's `answers` to an input named after that report.
- **Questions go down.** A person who receives a `Query` checks their own skills, keeps that in `State()`, and passes the query to all reports through one output (fmesh copies it to every pipe).
- **Answers come up.** Someone with no reports answers at once. A manager waits for every report with `component.RequireInputs`, merges, and sends one `Answer` up. Subtrees of different depth answer in different cycles: the early answers are kept until the last one arrives.
- **Built once, asked many times.** The same mesh answers "Go" and then "Rust".
- **Changing the tree means rebuilding the mesh.** Pipes are fixed once a mesh is built, so when Ivy takes on an intern the chart grows a sixth level and `getMesh` simply runs again. The run log then shows the uneven tree: managers on the shallow branches wait for the deep one, and the search takes 11 cycles.
- **Watch the wave.** `-frames dir/` writes one DOT graph per cycle with fmesh-export's `ExportCycle`, the components active in that cycle highlighted.

## Run

```bash
go run .

# Also write one highlighted graph per cycle, then render them
go run . -frames frames/
for f in frames/*.dot; do dot -Tpng "$f" -o "${f%.dot}.png"; done

# Regenerate the graph files (org chart-graph.dot / .svg)
FMESH_GRAPH=1 go run .
```
